# PopChoice

PopChoice is a movie recommendation app. Users describe their movie preferences, and the app recommends a movie based on their answers.

The project includes a local recommendation fallback and can use OpenAI embeddings with Supabase Vector Database when the required environment variables are configured.

## Features

- Collects the user's favorite movie and viewing preferences.
- Recommends a movie from the local movie collection.
- Supports semantic movie search with OpenAI embeddings and Supabase.
- Provides a fallback recommendation when the API configuration is unavailable.
- Responsive layout for mobile, tablet, and desktop screens.

## Requirements

- Node.js 18 or newer
- npm
- A Supabase project and OpenAI API key for vector search

## Installation

Install the project dependencies:

```bash
npm install
```

Start the development server:

```bash
npm run dev
```

Open the local URL shown in the terminal, usually:

```text
http://localhost:5173
```

To create a production build:

```bash
npm run build
```

## Environment Variables

Create a `.env` file in the project root:

```env
VITE_OPENAI_API_KEY=your-openai-api-key
VITE_SUPABASE_URL=https://your-project-id.supabase.co
VITE_SUPABASE_ANON_KEY=your-supabase-anon-key
```

To import the movies from `movies.txt` and generate their embeddings, add these
server-only variables to `.env` as well:

```env
VITE_OPENAI_API_KEY=your-openai-api-key
VITE_SUPABASE_URL=https://your-project-id.supabase.co
SUPABASE_SERVICE_ROLE_KEY=your-supabase-service-role-key
```

Run the importer from the project root:

```bash
npm run seed:movies
```

The importer uses the `text-embedding-3-small` model and can be run again safely
after adding or updating a movie. The service role key is only for this local
import command; never use it in `VITE_*` variables or commit it to the repository.

The application can run without these variables by using the local recommendation fallback. Do not commit the `.env` file to the repository.

## Supabase Setup

Run the following SQL in the Supabase SQL Editor:

```sql
create extension if not exists vector
with schema extensions;

create table if not exists public.movies (
	id bigint generated by default as identity primary key,
	title text not null,
	release_year integer not null,
	content text not null,
	embedding extensions.vector(1536)
);

create unique index if not exists movies_title_unique on public.movies (title);
```

Create the vector search function used by the application:

```sql
create or replace function public.match_movies (
	query_embedding extensions.vector(1536),
	match_threshold float,
	match_count int
)
returns table (
	id bigint,
	title text,
	release_year integer,
	content text,
	similarity float
)
language sql
stable
set search_path = public, extensions
as $$
	select
		movies.id,
		movies.title,
		movies.release_year,
		movies.content,
		1 - (movies.embedding <=> query_embedding) as similarity
	from public.movies
	where movies.embedding is not null
	  and 1 - (movies.embedding <=> query_embedding) > match_threshold
	order by movies.embedding <=> query_embedding
	limit match_count;
$$;
```

Allow the client to execute the search function:

```sql
grant execute on function public.match_movies(
	extensions.vector(1536),
	float,
	int
) to anon, authenticated;
```

The `movies` table must contain embeddings generated with the `text-embedding-3-small` model before semantic search can return results. The current application falls back to `content.js` when no matching vector result is available.

## Project Structure

```text
config.js       OpenAI and Supabase client configuration
content.js      Local movie collection and fallback data
index.html      Application entry page
index.js        UI rendering and recommendation logic
index.css       Responsive application styles
movies.txt      Movie reference data
vite.config.js  Vite configuration
```

## Security Note

The current frontend setup exposes `VITE_OPENAI_API_KEY` to the browser. This is suitable only for local development or demonstrations. For production, move OpenAI requests to a backend or serverless function so the API key remains private.
